## 3. 共用插桩代码 `pilot_shared/`

两个试点都依赖这套代码，**先把它写对再跑别的**。全部用 HF transformers，不用 vLLM（需要改注意力和 KV）。注意力实现设为 `attn_implementation="eager"`（需要注意力权重和自定义 4D 掩码）。

### 3.1 模块

| 文件 | 内容 |
|---|---|
| `models.py` | `load(model_name)` 返回 model、processor、工具格式适配器；支持 `deepeyesv2`、`minio3`、`qwen3vl8b`、`qwen25vl`（基座，仅前向） |
| `rollout.py` | 工具调用循环：生成 → 解析工具调用 → 执行裁剪 → 把返回图像插回 → 继续生成，直到给出答案或达到最大轮数（默认 8 轮、最大上下文 32K）|
| `origins.py` | 给序列中每个 token 标注来源（3.2）|
| `masking.py` | 按来源构造 4D 注意力掩码；支持「从哪些查询位置」到「哪些键位置」的屏蔽（3.3）|
| `hooks.py` | 残差流缓存与替换（激活修补）、逐头注意力权重读取、逐头输出缩放 |
| `scoring.py` | 在固定轨迹上计算 `log p(gold | 前缀)`；支持替换某次裁剪的图像后重算 |
| `prompts.py` | 各模型系统提示、Qwen3-VL 的工具定义、「请重新看图」用户回合（试点 A 基线用）|

### 3.2 token 来源标注

每条轨迹保存一个与 input_ids 等长的来源数组，类别：

- `sys`：系统提示与问题文本
- `img0`：原图视觉 token；另存每个视觉 token 对应原图中的像素框（由 Qwen 的 patch 网格和 `image_grid_thw` 计算，合并 2×2 后每个 token 对应 28×28 像素）
- `crop_k`：第 k 次工具返回图像的视觉 token（k 从 1 开始），另存该裁剪在原图坐标中的框
- `txt_pre_k`：第 k 次工具调用之前、上一次工具返回之后模型生成的文本（`txt_pre_1` 即第一次调用前的推理）
- `call_k`：第 k 次工具调用本身的文本
- `ans`：最后一次工具返回之后的推理与答案文本

### 3.3 掩码钩子

接口：`build_mask(origins, block=[(query_set, key_set), ...])`，返回加性 4D 掩码（被屏蔽处为 `-inf`），与因果掩码相加后传给模型前向。`query_set` 和 `key_set` 用来源类别或位置区间表示。要求：

- 不屏蔽任何东西时，logits 与不传掩码时**逐位相同**（容差 1e-3）。
- 位置编码（Qwen 的 M-RoPE）不受影响：只改掩码，不删 token。

试点 B 第 6.5 步需要**真实驱逐**（从 `DynamicCache` 中删掉对应位置的 K/V），在 `masking.py` 里另写 `evict(cache, positions)`。删除后已施加的旋转位置编码保留，后续 token 的位置编号继续递增，不要重排。

### 3.4 共用轨迹

在 V*、HR-Bench 200、VisualProbe-Hard 上，对 DeepEyesV2、Mini-o3、Qwen3-VL-8B 各跑：

- 1 条贪心轨迹（温度 0）
- 4 条采样轨迹（温度 0.7，种子 0–3），试点 A 用于判断答案是否稳定

保存为 `${WORK_DIR}/traj/{model}/{dataset}/{qid}_{seed}.pt`，内容：`input_ids`、`origins`、各次工具调用的框、各工具返回图像（存路径即可）、最终答案、是否正确、轮数、总 token 数、各来源 token 数。另存一份汇总 `traj/{model}/{dataset}/index.jsonl`。

### 3.5 检查点 S（10 月 7 日晚之前全部通过）

- S1：用 `rollout.py` 跑出的 V* 准确率与 1.4 中官方脚本的结果相差 ≤ 2 个百分点。
- S2：空掩码与不传掩码的 logits 逐位一致。
- S3：屏蔽「`ans` → 全部 `crop_k`」后，对一条已知依赖裁剪的样本，`log p(gold)` 明显下降（随手挑 5 条正确样本，至少 3 条下降 > 1 nat）。
- S4：来源标注抽 3 条轨迹人工核对：视觉 token 数与 `image_grid_thw` 一致，每段文本归属正确。
- S5：`evict` 后继续生成不报错，且驱逐 0 个位置时输出与不驱逐完全相同。

## 5. 试点 A：机制（能否找到一条具体路径）

样本范围：V* 与 HR-Bench 200 上的全部轨迹，三个模型。

### 5.1 有效裁剪与裁剪敏感度

**有效裁剪**：某次裁剪框完全包含目标框，且 IoU(裁剪框, 目标框) > 0.5。没有目标框的样本不参加试点 A。取一条轨迹中**最后一次有效裁剪** t* 作为分析对象。

**裁剪敏感度（teacher forcing）**：固定贪心轨迹的全部文本，只把第 t* 次返回的图像替换掉，重算 `log p(gold)`（多选题取选项字母 token 的对数概率；其余取答案 token 对数概率之和，答案位置为 `ans` 段中答案开始处）：

```
CS = log p(gold | 真实裁剪) − mean_k log p(gold | 扰动裁剪 k)
```

三种扰动，**分别保存**，另存三者均值：

1. `rand_same`：同一原图上与目标框不重叠、尺寸相同的随机裁剪（3 个随机位置取均值）
2. `blur`：真实裁剪做高斯模糊（σ = 裁剪短边的 1/10）
3. `cross`：另一张图上尺寸相同的裁剪

替换后的图像尺寸与原裁剪相同，保证视觉 token 数不变。输出 `pilotA/cs.jsonl`，每行含 qid、model、t*、三种 CS 与均值。

参考：The Illusion of Visual Tool-Use 的代码（`github.com/OpenCausaLab/CauAudit`）实现了类似的逐步反事实替换（Visual Evidence Gain），可借鉴其替换流程，但本试点的定义以本节为准。

### 5.2 排除三种假象，得到干净样本（V1）

对每条有有效裁剪的贪心轨迹，依次判断：

1. **错误裁剪**：已由 5.1 的有效裁剪定义排除。
2. **证据冗余**：让同一模型**不调用工具**直接作答（提示中禁止工具，或把工具输出替换为空并要求立即作答，以各模型最自然的方式为准，写进笔记），采样 4 次。若 ≥ 3 次答对，记为冗余，排除。
3. **固定后续文本造成的假象**：把第 t* 次裁剪换成 `rand_same`，从该处起**重新生成**后续推理和答案，采样 4 次（温度 0.7）。

**干净的「没用上」样本（G_unused）**：非冗余，`CS_mean < 0.2`，且第 3 步 4 次重新生成中 ≥ 3 次的答案与原答案相同。按原答案对错再分为 `G_unused+` 与 `G_unused-`。

**「有效看」样本（G_use）**：非冗余，`CS_mean ≥ 1.0`，且第 3 步 4 次中 ≥ 2 次答案改变。

输出 `pilotA/groups.jsonl`（每行 qid、model、split、组别、各项中间量）与 `pilotA/groups_summary.csv`（每个模型每个数据集：总轨迹数、有效裁剪数、冗余数、G_use、G_unused+、G_unused- 的数量）。

### 5.3 编码探针与提前定答（V2 的前提）

**编码探针**：标签 z 用正确选项（V* 为四选一，机会水平 25%；HR-Bench 同理按选项数计算）。对每层 ℓ，把第 t* 次裁剪的全部视觉 token 在该层的隐藏状态取平均，训练 L2 正则的 logistic 回归（scikit-learn，`C` 用 5 折交叉验证选），按图像做 5 折交叉验证。只用**定位半区**。分别在 G_use 和 G_unused 上报告逐层准确率曲线和最大值。

两个对照：

- 随机标签：打乱 z 后重训，最大准确率应 ≤ 机会水平 + 5。
- 扰动裁剪：把裁剪换成 `rand_same` 后的隐藏状态，准确率应接近机会水平。

**提前定答**：在第一次工具调用（`call_1`）开始前的位置截断，追加一段强制作答的文本（例如 `Answer: (` 或该模型答案标签的开头），读取各选项的概率。定义**定答强度** `commit = p(该轨迹最终答案的选项 | 调用前前缀)`。在 G_use 与 G_unused 上分别报告分布。再用同样方式在第 t* 次裁剪**返回之后、模型生成任何文本之前**读一次，记为 `commit_post`。

输出 `pilotA/probe_layers.csv`、`pilotA/commit.jsonl`。

**检查点 A3**：若 G_unused 上裁剪探针的最大准确率 ≤ 机会水平 + 10，说明是感知失败（信息根本没编码），V2 直接判不通过，试点 A 记录结果后停止 5.4、5.5。

### 5.4 路径干预（V2）

用 3.3 的掩码钩子，在**定位半区**的固定贪心轨迹上做以下屏蔽，每种都在 G_use 和 G_unused 上算 CS 的变化（与 5.1 同样的扰动定义），并在 G_unused- 上用重新生成（4 次采样）测翻转为正确的比例：

| 编号 | 屏蔽（查询 → 键） | 目的 |
|---|---|---|
先定义两类查询位置：**答案位置**为最终答案 token 及其前一个位置；**中间文本**为第 t* 次裁剪返回之后、答案位置之前模型生成的全部文本。

| 编号 | 屏蔽（查询 → 键） | 目的 |
|---|---|---|
| P1 | 答案位置 → `crop_t*` | 直接路径：答案直接读裁剪 |
| P2 | 中间文本 → `crop_t*`（答案位置仍可读裁剪）| 间接路径：经由后续文本转述裁剪 |
| P3 | P1 + P2 同时 | 排除绕路补偿（Pathways 2607.03358 指出单独屏蔽一条路径时模型会改走另一条） |
| P4 | 答案位置与中间文本 → 第 t* 次调用之前的全部模型生成文本（各 `txt_pre_k` 与 `call_k`，k ≤ t*）| 「先入为主」假设：切断调用前已形成的文本判断 |
| P5 | 与 P4 屏蔽数量相同的随机文本位置 | P4 的对照 |

层范围：先全层屏蔽；P1、P3、P4 再做 4 层滑动窗口（步长 1），记录效应最大的窗口。

如果「先入为主」不成立，可以基于 5.3 和本节结果提出另一条具体路径并按同样标准检验，但必须在 `pilotA/mechanism_note.md` 里写清楚它是什么、在哪些层、怎样干预，并且在 10 月 11 日之前定下来。

输出 `pilotA/interventions.csv`（每行：model、样本组、干预编号、层窗口、平均 ΔCS、翻转率、样本数）。

### 5.5 预测与干预对比（V3）

所有超参在定位半区确定后，**冻结**，在留出半区上只跑一次。

**预测**：用机制给出的单样本分数（默认是 5.3 的 `commit`；若换了机制，用对应的分数）预测「有效裁剪且非冗余」的轨迹属于 G_unused 还是 G_use，报告 AUROC。

**干预**：把机制导出的干预做成一个推理时方法（默认：当 `commit > τ` 时，在第 t* 次裁剪返回后执行 P4 型屏蔽并重新生成；τ 在定位半区上选），在留出半区的**全部样本**上正常运行（从头生成），与以下基线比较准确率：

| 基线 | 做法 | 超参 |
|---|---|---|
| 不干预 | 原模型 | — |
