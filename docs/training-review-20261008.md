# Visual Agent 近两周训练复盘与续训建议

核对日期：2026-10-08。范围：2026-09-25 至 2026-10-08 的主要多工具训练分支及已落盘评测。
代码分析基于本地 `f89ada2`；训练进程的实际行为以对应日志和 rollout 为准，不能用当前脚本默认值替代历史配置。
本文记录一次只读审阅，不代表已经实施建议、修改训练配置或提交新作业。

## 1. 决策结论

1. **新数据 64 卡主线支持短段继续训练。** step53→69 的主要准确率指标均改善；提交前补齐的 ChartQA 为78.28，FSC147 MAE为15.65、有效率100%。建议到下一个固定验证点，例如 step80，再决定后续预算；HRBench、CV3D和MME仍落后于旧64卡step80，不能认定它已全面超过旧版本。
2. **旧 VL-OCR 64 卡 step80 保留为综合能力基线。** 它在 HRBench、CV3D 和 MME 上仍有优势。旧 16 卡分支应优先补评验证最优的 step160，已有结果不支持默认从最终 step210 继续堆步数。
3. **下一轮优先解决计数的学习信号与工具证据。** 多组 FSC147 的 16 条采样奖励完全相同，模型又只收到一个 count，增加同类数据或采样数未必带来有效更新。
4. **补齐选模验证集。** 当前验证没有单列 HME、FSC147、MME 驾驶/监控和工具纠错能力，无法约束这些能力退化。
5. **反事实训练保留为独立实验分支。** 普通 RL 已有较强 OCR 抗干扰表现；反事实方法必须在匹配预算、堵住绕过后超过 vanilla，并保持 clean 能力，才能支持扩大投入。

证据强度区分：版本分数、轨迹统计和代码行为属于已观察事实；能力退化的因果解释、数据配比与超参数调整属于待验证建议。本文没有把跨工具、跨奖励版本的差值当作纯 RL 增益。

## 3. RL 配置、学习信号与数据

### 3.1 已核对的主要训练设置

| 项目 | 新数据 64 卡 | 旧 16 卡 / v2-lite 的对应设置 |
|---|---:|---:|
| 训练 GPU / 工具 GPU | 56 / 8 | 14 / 2 |
| Train batch | 336 | 126 |
| PPO mini-batch | 112 | 42 |
| 每题采样 n | 16 | 16 |
| Actor 学习率 | 1e-6 | 1e-6 |
| Actor KL 系数 | 0.001 | 0.001 |
| 训练 / 验证 temperature | 1 / 0 | 1 / 0 |
| 最大 assistant 轮次 / 每轮 token | 8 / 512 | 8 / 512 |
| Prompt / response 长度预算 | 8192 / 16384 | 8192 / 16384 |

使用 GRPO，KL 在 actor loss 中，不作为 reward 中的 KL。response 长度预算还包含工具观察、图像和模板 tokens，不能理解成可生成 16,384 个回答 tokens。

当前奖励主要是 `0.9 × acc + 0.1 × format − query_penalty`；调用工具本身不加分，格式分也不要求长 reasoning。没有证据支持为了提高分数而奖励工具调用次数或解释长度。

日志抽查显示：新 64 卡 step69 的截断率约 0.1%，step53 约 0.3%，不支持把主要能力短板归因于大面积超长截断。不同 step 使用不同题目，单步训练 reward 上升不能直接解释成泛化提升。

### 3.2 n=16 下的实际组内差异

按 `(data_source, source_index, question, reliance_branch)` 分组；下表样本组均为 16 条轨迹。使用保存的完整 `score` 判断是否有差异，不只比较答案准确率。

| Run / step / 来源 | 组数 | score 有差异的组数 | 全部回答错误的组数 |
|---|---:|---:|---:|
| 新 64 卡 step10，FSC147 | 31 | 2 | 19 |
| 新 64 卡 step53，FSC147 | 35 | 0 | 23 |
| 新 64 卡 step69，FSC147 | 23 | 1 | 13 |
| 新 64 卡 step53，所有来源 | 336 | 69 | — |
| 旧 16 卡 step210，所有来源 | 126 | 17 | — |

这些是指定 step 的完整采样批次，不代表整个训练期比例。FSC147 在这些批次平均每条轨迹约调用一次工具，常见行为是 `object_count → 原样输出 count`。

GRPO 按组减去平均奖励；当组内奖励一致时，终局奖励不提供组内策略排序信号，KL 等项仍可作用。**“全错且没有有效探索”的题，重复采样16次不会自动变成可学习数据。**

建议按顺序验证：

1. 提供能改善决策的空间证据和替代动作；用少量经过核验的成功轨迹示范分区计数、定位指定实例和工具失败后的有效恢复。
2. 对计数试验有界误差分与精确正确分的组合，同时监测偏向常见数量的退化。奖励设计必须用实际候选轨迹验证能否产生有意义的排序；若所有预测一样，连续奖励也没有帮助。
3. 在相同问题池和采样预算下比较 n8/n16，记录有差异的组数、有效回答数、工具耗时、生成 token 和 GPU 小时。不能从历史异协议 n8/n16 分数直接选方案。
4. 保留 GRPO、当前学习率与 KL 作为初始对照；先解决信号问题，再单独试验学习率或 KL。当前证据不足以把退化归因于某个超参数。

## 4. Prompt 与模型实际收到的证据

### 4.1 指定实例优先于重新检测

当前 [VL-OCR prompt](../prompts/visual_agent_rl_system_multitool_vlocr.txt) 要求深度比较先 `grounding_detect` 再测量。

已核对的 CV-Bench-3D `index=21`：题目指定红框后方椅子和蓝框书本；模型检测后选择了前景椅子框和大书架区域，测得 2.2686/2.788，随后把这些数值称为红蓝框目标的深度。数值比较正确，目标对应错误。

建议改为：题目已有明确框时先识别指定区域；需要检测时，把候选实例与题目指代匹配后再测量。可在一次 `depth_measure` 调用中比较同一张图的多个框。模型发出的错误框已在原始调用中出现，不能把该例归因于工具把正确坐标转换错了。

### 4.2 计数工具的证据不足

日志保存 count、点和框，但训练与评测的模型观察被压缩为 `{"count": ...}`。因此“检查工具重复检测和漏检”需要接口提供支持，不能仅靠 prompt 要求完成。

建议在计数对照实验中提供紧凑空间证据，例如标记图或必要的点/框；控制长度，检查是否改善计数和核查行为。不要把日志可见的完整返回误认为模型也看到了。实现位置：[评测观察转换](../scripts/visual_agent_inference.py)、[训练工具观察转换](../reinforcement_learning/verl/tools/visual_tool.py)。

### 4.3 其他短规则

- 检测为空只表示没有检测到；结合原图、相关裁剪或具体查询词决定下一步。
- 裁剪产生新图像后，坐标必须对应当前 `target_image`。
- 区分“以上选项均不正确”和“图中不存在该物体”；计数不在选项中不证明物体不存在。
- 只有文字有助于问题时才调用 OCR；颜色、材质题不需要机械地追加 OCR。
- 达到可靠结论后停止调用；最终答案与可见证据一致，不为凑 reasoning 追加解释。

训练和评测应共同使用修改后的行为规则，并保留旧 prompt 的同权重对照。直接改变评测 prompt 得到的提升，不能记成权重训练收益。

## 5. 选模与评测协议

### 5.1 验证集覆盖不足

当前 1,312 条验证记录的来源与独立图像路径数：

| 来源 | 题数 | 独立图像路径数 |
|---|---:|---:|
| HRBench4K | 800 | 177 |
| depth | 84 | 53 |
| TallyQA | 108 | 100 |
| Chart | 160 | 160 |
| OCR | 160 | 158 |

当前选模是五来源准确率等权宏平均；800 条 HRBench 记录并非800张独立图片。新增 HME、FSC147、MME 场景和抗工具错误能力没有独立选模项。

建议保留原验证用于历史追踪，新增独立开发样本覆盖 HME、稀疏/密集计数、复杂场景、指定实例和工具纠错。图像变体及同图不同问题应按图像划分，统计不确定性时也按图像聚合。HRBench4K 已参与选模，报告中明确其开发集角色；最终泛化结论使用未参与选模的数据。

旧16卡验证宏平均在 step160 为 74.63%，到 step200 为 71.87%。新主线 step53 为69.69%，v2-lite step50 为68.73%。后两者与旧分支的奖励版本及数据不同，不能只据这个宏平均排序。

### 5.2 奖励与外部评分口径

- Chart 奖励在历史中从5%容差变为精确数值匹配；当前非关系题规则失败还会进入语义 judge。外部 ChartQA_TEST 使用规则评分和5%容差。旧新训练验证分数不能无条件比较。
- 年份、类别和选择标签保持精确；连续数值任务是否接受近似需要明确规定。同时保存 exact 与 benchmark-compatible 指标，避免奖励目标和验收目标混淆。
- 对选择题、可规范化的整数计数优先使用确定规则；开放文本再使用语义 judge。不要让模型裁判替代本可精确判断的答案。
- 当前 MME 解析会搜索文本中的 A–E，错误提示中的字母也可能被当作答案。step69 中 API失败、超轮次、残留工具调用等无效输出，Lite 20条中4条被记正确，CN 80条中18条被记正确。应统一标记无效并重算，不能只修某个候选模型。
- FSC147 同时报告有效率和有效子集误差；不能把空的总体 MAE 填成 MAE_valid。
- HRBench 保持 Average/all；OCR 原词面分、反斜杠归一化分和语义重判分分别报告，不混成同一条成绩曲线。

主 judge 在一些运行中大量403，但检查到的 judge batch 汇总由备用服务接住，`final_unresolved=0`。这说明存在请求浪费和服务依赖，不支持直接断言大规模奖励缺失造成低分。

### 5.3 输入与预算仍需固定

新 VL-OCR 评测已经使用训练 prompt、native tool schemas、Hermes、8轮和每轮512 token。但仍需记录和核对：

| 项目 | 观察到的状态 | 对后续比较的要求 |
|---|---|---|
| 图像预算 | RL 默认约236万像素；外部评测发送原图，服务入口未显式施加相同上限 | 核对实际 image grid/视觉token，固定预算或分开报告不同预算 |
| 上下文预算 | RL prompt8192/response16384；外部 max_model_len32768 | 相同轮次不等于相同总上下文预算 |
| 评测补测 | 部分历史结果合并了成功预测与仅失败补测 | 标记首次/补测结果、失败数及规则 |
| 工具版本 | 拆分OCR、VL-OCR、native与历史prompt-only协议不同 | 固定工具权重、schema、返回字段与服务配置 |
| 训练步数 | 64卡 batch336，16卡 batch126，部分分支还继承历史训练 | 对齐采样行数、生成token、更新与GPU小时，不能只对齐step |

例如，从 base 开始的64卡 step53 约消耗17,808训练行，16卡 step50 约消耗6,300行；n均为16。带固定前缀的数据还会改变有效生成长度和独立题目覆盖，匹配行数也不是完整预算控制。

## 6. 反事实训练的当前证据

截至本次核对，OCR依赖评测已完成 base 与 vanilla53 的三条件结果：

| 模型 | clean | 原训练型干扰 | 形近字干扰 |
|---|---:|---:|---:|
| base | 85.8 | 58.6 | 73.2 |
| 普通RL vanilla53 | 86.7 | 84.1 | 84.3 |

这是整套OCRBench准确率；不同模型可能调用不同区域，错误暴露不完全相同。必须再比较确实遭遇同一错误的交集，不能把整套分差全部归因于纠错机制。当前未见 v2 的完整三条件结果，因此无法判定其优于 vanilla。

已有 v2-lite step29–39 OCR反事实机制审计：60组、960条轨迹；HME 50组中只有4组答案正确性混合。246条轨迹通过等价参数改写取得正常OCR响应，另有全图crop别名绕过候选；部分HME扰动还修改LaTeX命令名，产生明显异常线索。

`f89ada2` 已修复等价参数/图像别名重放，并约束HME扰动、答案残留和子来源替换上限。旧 `v3_strict10` 数据不满足新要求，不应沿用旧候选数量；审阅时新的 `v3_fixed` 数据尚未生成。详情见[机制审计与修复记录](../experiments/visual_agent_execution_plan/ocr_mechanism_v3_20261008.md)。

下一步保留 vanilla、factual-only、paired 三臂：同初始权重、来源及子来源、题目重复程度、训练预算和judge。观察 clean 能力、同错误暴露子集、真实OCR错误、绕过率与工具成本。只有 paired 相对对照有增益且不损害基础能力，才支持扩大反事实训练投入。
